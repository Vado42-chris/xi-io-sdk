# ROTFL User × Experience Socratic Binary Decomposition ABI

Status: reusable public-safe SDK contract  
Scope: white-label decomposition of human/user experience problems into the smallest testable binary denominators, reusable templates, primitives, and affected-only HOT_PATCH work.

## Core identity

```text
U = USER / HUMAN
X = EXPERIENCE
UX = USER × EXPERIENCE
```

The human is the User. The thing being designed, tested, operated, reviewed, or endured is the Experience.

This contract does not define one UI discipline. It defines a universal method for reducing any human-facing or agent-facing experience into the smallest useful questions the system can test without losing the whole-experience denominator.

## Socratic binary rule

The operational Socratic method is a sequence of smallest sufficient questions.

Each question MUST target one irreducible uncertainty that can be represented through the binary ABI:

```text
QUESTION
-> CURRENT DENOMINATOR CELL
-> TEST / OBSERVATION
-> KNOWN_BIT + VALUE_BIT
-> EVIDENCE REF
-> NEXT QUESTION | HOT_PATCH | NO_EFFECT | TRUE_WAIT | TERMINAL
```

Hard:

```text
QUESTION != ANSWER
TEST != TRUTH OWNER
UNKNOWN != FALSE
PROSE CONFIDENCE != KNOWN_BIT
ONE TEST PASS != WHOLE EXPERIENCE PASS
MORE QUESTIONS != MORE VALUE
SMALLEST QUESTION != LOSS OF WHOLE DENOMINATOR
```

The preferred next question is the smallest question whose answer most reduces decision-relevant uncertainty for the current User × Experience.

## Tests are template and primitive generators

A test is not only a validator. Repeated structurally equivalent tests reveal reusable shapes.

```text
TEST OCCURRENCE
-> OBSERVED INPUT / EXPECTED / ACTUAL / LIMIT
-> STRUCTURAL EQUIVALENCE
-> TEST TEMPLATE
-> REUSABLE PRIMITIVE CANDIDATE
-> SECOND-CONTEXT / HOSTILE PROOF
-> ACCEPTED PRIMITIVE
```

The system should ask:

- what is the smallest variable this test actually measures?
- what invariant does it protect?
- what evidence proves it?
- what user/experience surfaces consume it?
- is this recurrence the same primitive with different values?
- can this test become a reusable template rather than another bespoke checklist?

Hard:

```text
TEST_CASE != PRIMITIVE
REPEATED WORDING != STRUCTURAL EQUIVALENCE
ONE ADOPTER != UNIVERSAL
TEMPLATE != DOMAIN TRUTH
PRIMITIVE != AUTHORITY
```

## Smallest common denominator

For a current problem, recursively decompose until every leaf is independently answerable, evidence-bindable, and action-routable.

A valid leaf has:

```text
VARIABLE_ID
USER_REF
EXPERIENCE_REF
QUESTION_ID
KNOWN_BIT
VALUE_BIT
REQUIRED_BIT
EVIDENCE_REQUIREMENT_REF
AFFECTED_CONSUMER_REFS
OWNER_REF
NEXT_ON_TRUE
NEXT_ON_FALSE
NEXT_ON_UNKNOWN
```

Stop decomposition when further splitting would no longer change routing, proof, ownership, or decision quality.

Do not split merely to increase counts.

```text
ATOMIC_ENOUGH
= independently testable
+ independently evidence-bindable
+ independently routable
+ no material decision hidden inside the cell
```

## Whole-experience preservation

Binary decomposition MUST preserve the parent User × Experience denominator.

```text
LEAF PASS != PARENT PASS
ACCOUNTING_100 != CLOSURE_100
LOCAL OPTIMUM != USER EXPERIENCE SUCCESS
```

Every parent recomputes from current required children after any material delta.

A leaf may be locally correct while the Experience remains wrong because:

- another required leaf is false or unknown;
- the user's next action is unclear;
- the proof is unlocatable;
- the sequence is wrong;
- accessibility/cognitive load fails;
- an affected consumer was omitted;
- a stale predecessor remains selectable.

## Binary Socratic conductor

Ibal/foreman conductors consume current graph + binary denominator and select the minimum next question/work formation.

```text
CURRENT USER × EXPERIENCE
+ CURRENT GRAPH
+ CURRENT BINARY DENOMINATOR
-> HIGHEST DECISION-RELEVANT UNCERTAINTY
-> SMALLEST SUFFICIENT QUESTION
-> MINIMUM QUALIFIED TEST/OBSERVER/MINER
-> RESULT DELTA
-> AFFECTED-ONLY RECOMPILE
```

The conductor does not answer a question by consensus or prose. It routes evidence-producing work.

## Observer / miner split

```text
OBSERVER
  asks/tests/compares
  returns observed bits + evidence
  does not mutate

MINER
  receives a known mismatch / targetable unknown
  produces HOT_PATCH or typed HOLD

FOREMAN
  applies/holds/rejects patch
  recomputes affected denominator
```

Hard:

```text
OBSERVER != MUTATOR
MISMATCH != AUTOMATIC PATCH
UNKNOWN != WORK AUTOMATICALLY
CANARY != MINER
MINER != FOREMAN
```

## Experience test families

The same method applies across domains.

Examples:

- UI: can the User perceive, understand, act, recover, and verify?
- legal workflow: can the User identify what to sign, serve, file, prove, and do next?
- publishing: does the reader/editor experience preserve brief, claims, sources, navigation, accessibility, and release intent?
- agent workflow: can a cold worker identify role, current state, tools, denominator, next action, effect ceiling, return target, and proof without archaeology?
- provider integration: is capability present, current, qualified, authorized, attempted, read back, and understood by the User?
- billing/metrics: did a verified unit occur, did it reduce work/risk, and is it rate-mapped without confusing quality with money?

## Question economics

Prefer questions by force multiplication:

```text
QUESTION_VALUE
~ affected required cells clarified
+ reusable test/template value
+ owner/manual recovery eliminated
+ repeated defect prevention
- coordination cost
- effect risk
- duplicated observation
```

This is a prioritization heuristic, not an opaque universal score.

## Rebase heartbeat

After any material Result:

```text
RESULT
-> RETURN / APPLY_RETURN
-> REAP stale/duplicate/superseded selectors
-> changed-only REBASE
-> RE-ONBOARD from current refs
-> recompute USER × EXPERIENCE denominator
-> ask next smallest sufficient question
```

A rebase is a heartbeat, not a restart.

Hard:

```text
REBASE != REDISCOVER EVERYTHING
REBASE != DROP CURRENT USER
REBASE != DROP REQUIREMENTS
REBASE != WHOLE PORTFOLIO REPLAY
REBASE = REBIND CHANGED CURRENT TRUTH + PRESERVE PROVEN NO_EFFECT
```
