# Universal X-Intersection UX Contract v1

Status: candidate executable SDK primitive.

This contract binds the reusable owner-derived geometry for deadline-safe fractal work without replacing existing ACK, ROTFL, X42/X43, Cadence, or Studio ownership.

## Geometry

- `/` = one levelled pipeline.
- `\\` = the complementary levelled pipeline.
- One is GOLDEN, one is SUB.
- Their X intersection is the comparison/fan-in diff.
- `|` = global timeline + priorities. The X must meet the required deadline coordinate.
- FLOOR, MID, and symmetrically-derived TOP are the 10s flatplane at each fractal level.
- Complete rotation of that flatplane with an explicit sector denominator produces the 100s accounting for the step.
- A complete 100s result is a PATCH candidate only. It is not a revision, current selector, or authority grant.

## Studio registry intersection

Every project in the supplied current Studio registry denominator must receive one disposition at every intersection:

`AFFECTED | NO_EFFECT | N_A | UNKNOWN`

AFFECTED projects require the applicable SDK ACK and complete Result -> RETURN -> APPLY_RETURN chain. Available teammate help must have an explicit disposition. This is all-and-only accounting, not one-worker-per-project and not universal mutation authority.

## HVT / MVPD

HVT and MVPD work uses double force-multiplier projections, GOLDEN and SUB, with one foreman fan-in. Existing QUANTIZE_BEFORE_FRACTALIZE, canary/miner/foreman rank boundaries, triage, self-triage/aftercare, RETURN/APPLY_RETURN and reap semantics remain authoritative.

## Hard invariants

- TRINITY_WITHOUT_TIMELINE_PRIORITY_SPINE != COMPLETE_TRINITY
- FLATPLANE_10S != ROTATED_100S
- ROTATION_COVERAGE_100 != CLOSURE_100
- 100S_COMPLETE != PATCH_ACCEPTED
- PATCH != REVISION
- REGISTERED_PROJECT_OMITTED != COMPLETE_INTERSECTION
- AVAILABLE_TEAMMATE_HELP_IGNORED != FAN_IN
- NO_REPLY != NO_EFFECT
- UNKNOWN != N_A
- PROJECT_COUNT != WORKER_COUNT
- ONE_CHILD_RED != ROOT_RESTART
- FRACTAL_ERROR != RESTART
