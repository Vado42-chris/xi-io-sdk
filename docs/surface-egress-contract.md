# Surface egress contract

WordPress is a plugin/provider egress surface, not a separate orchestration plane.

Hard:
- canonical Work precedes provider projection
- WordPress uses the same egress lifecycle as Slack, mail, Drive, GitHub, Cloudflare and document/media outputs
- provider registry size does not grant authority
- provider object identity does not replace canonical Work identity
- one blocked egress does not stop the root
- Work terminal does not imply root terminal
- provider readback does not imply owner acceptance

WordPress is the high-cardinality HVT because its plugin, capability, content-type, taxonomy, media, theme and site registries are much larger than most adapters.
